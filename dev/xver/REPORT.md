### Delta 9 deserves its own paragraph

This was the most user-visible change in NEWS and it had **never been executed** —
`pseudobulk_samples()` refuses fewer than four samples and the committed fixture
has three, so all three pseudobulk steps were recorded as identical errors on both
versions. An identical error reads as "no difference" while testing nothing.

With a 5-sample fixture, and again on the real Thrane data:

- `@misc$scaled_pbulk_mtx` is **identical** on both versions, so the oracle
  compares like with like rather than two different inputs.
- alex's displayed genes are exactly the top-k by `sd/mean` (the true CV).
- main's displayed genes are exactly the top-k by `mean/sd` (the inverted form).
- The two selections **overlap in 0 of 5** genes on the fixture and **0 of 10** on
  the Thrane data.

So main did not merely order the genes differently: it displayed a completely
disjoint, least-variable gene set. NEWS's advice to regenerate 1.2.x heatmaps is
if anything understated.

## Is NEWS's ordering claim true?

NEWS says of the ordering fix: *"no expression values changed — every count,
transformed count, and gene-level statistic is identical once reordered."*

**Mostly true, and now measured.** Matched by name rather than by position:

- `@counts`, `@tr_counts`: multisets **bit-identical**, max absolute delta exactly
  `0`.
- `@gene_meta` `vst.*` columns: **no difference at all** — the expectation record
  for vst float drift went unobserved.
- 10,417 of 12,111 raw differences vanish under canonicalization: they are pure
  reordering.
- Residual float noise elsewhere peaks at **2.9e-14** scale-relative.

**But four things do change value, and none are in NEWS.** All four were proven to
be order sensitivity that already existed in 1.2.2 — `dev/xver/30_order_probe.R`
permutes spot order inside a *single* build and reproduces each one, so the
refactor did not introduce them; it changed the order they were always sensitive
to.

1. **`STenrich` p-values.** `stenrich_perm_one_combo()` does `set.seed(seed)` then
   `computeSubsampleSums(coords_mat, …)`, and the C++ draws
   `Rcpp::sample(all_indices, …)` over **row positions**
   (`src/spatialge_helpers.cpp`). Same seed, different rows ⇒ a different null
   distribution. The observed statistic is safe (character-indexed); only the
   p-value moves.
2. **`SThet(k=)` Moran's I — the largest effect found.** The kNN graph on a regular
   grid has tied k-th distances broken by position, so reordering yields a
   different neighbour graph. Moran's I moves by up to **1.8e-2** — three
   significant figures, not float noise. The default distance-based `listw` is
   unaffected (~1.5e-15).
3. **`STgradient(distsumm='avg')` Spearman correlations.** Averaging distances
   creates exact ties; a 1e-16 summation-order change flips a tie, which flips a
   rank, which moves the correlation by up to **4.3e-3**. `distsumm='min'` does not
   create the same ties.
4. **`plot_counts()` density curves.** It does `set.seed(subset_seed)` then
   `df[sample(1:nrow(df), nrow(df)*distrib_subset), ]` — again a seeded draw over
   **positions**, so a different 50% of spots is plotted. Cosmetic, but an output
   change. `ggforce::geom_sina`'s jitter behaves the same way.

Consequence worth flagging beyond the wording: **`SThet(k=)` and
`STgradient(distsumm='avg')` are not reproducible across two files describing the
same tissue with rows in a different order** — on either version. The fix made
ordering deterministic given the coordinates, which removes the *file-layout*
dependence, but the tie-breaking sensitivity itself remains.

## Also found: an undocumented change in error text

22 paths. `resolve_samples()` (`R/utils_validate.R:92`) reads its slot with
`names(methods::slot(x, slot))` where main used `x@slot` inline, and R words those
two failures differently:

- main: ``no applicable method for `@` applied to an object of class "NULL"``
- alex: `cannot get a slot ("tr_counts") from an object of type "NULL"`

Both still error, so nothing is broken and this is not a regression. Worth noting
for two reasons: the message a user sees changed across roughly ten exported
functions, and the sweep incidentally shows that **neither** version gives a
friendly error here, because `resolve_samples()` runs before any
`assert_stlist()` class check.

## Cluster labels: partitions are safe

`STclust` labels are order-sensitive (`hclust` breaks the fixture's saturated
distance ties by input order), which risked a silent cascade: labels feed
`annot=`/`domain=`/`ref=` into `STenrich`, `STgradient` and `STdiff`, so a
relabeling would have the two versions answering different questions while both
looked order-only. Checked explicitly as a partition (each cluster keyed by its
minimum member): **24 of 24 clusterings have identical partitions.** The cascade
does not materialize. A pinned-annotation scenario (S11) was run anyway so the
three downstream functions are also verified independently of `STclust`.

One genuine selection difference did appear: `STgradient` at `topgenes=100` picks
`Gene168` on main and `Gene158` on alex — a rank flip at the cut. Everything
downstream of it is reported as `SELECTION_CASCADE` rather than compared row by
row, because the two versions computed statistics on different genes.

## Coverage debt, stated rather than implied

- **89 of 202 compared steps compared only an error string.** These are mostly the
  deliberate invalid-input probes (S6, S7), where an identical error *is* the
  contract. But it is also how delta 9 hid for a month, so the count is reported
  rather than folded into a pass.
- **Deltas 12 and 13 are not verified.** Both need a construction not built here;
  delta 12's guard additionally requires a non-converging `spaMM` fit, which
  `dev/ARCHITECTURE.md` fidelity rule 2 says the fixture policy deliberately avoids.
- **Deltas 14, 15** are documentation, outside an output comparison. A cheap check
  exists: `tools::Rd2ex(commentDonttest = FALSE)`.
- Not reached at all: the Seurat input path, `geomx`, the other
  `detect_input_cases.R` handlers, Windows (`resolve_cores` forces 1 core),
  `calc_umap=TRUE`, and `sct` at `cores>=2` (both structurally non-reproducible per
  fidelity rule 1).
- Only pixel-independent plot content is compared (built data, labels, scales,
  facets, coords). Two plots with identical built data could still render
  differently.
- One dependency set is held fixed. This says nothing about how 1.2.2 behaved on
  the dependency versions its users actually had.

### Harness self-checks that had to pass first

- Producers assert they loaded the intended library **and** version, and never use
  `devtools::load_all()` (which would silently make both children alex).
- `xv_assert_plain()` refuses to serialize any environment, closure, S4 object or
  external pointer, and the comparator runs with `spatialGE` absent from its
  library path — so a leak fails loudly instead of deserializing against the wrong
  class table.
- The reducer errors on an unrecognized class rather than returning `NULL`; a
  tolerant reducer manufactures clean comparisons, because `NULL == NULL`.
- Reduction is checked to be deterministic (reduce twice, compare).
- The comparator asserts the two payloads' 44 dependency versions and `LC_COLLATE`
  match before comparing anything.
- Classification fails closed: no matching record means `REGRESSION`, and
  `sum(per-class counts) == total observed paths` is asserted.
- The inverse `MISSING_EXPECTED` check requires every claimed fix to actually be
  *observed*; it is what surfaced that delta 9 and delta 8 were unreachable.

### Corrections made to the harness during the run

Recorded because each was initially producing a wrong answer, and three of them
produced *false* alarms rather than false clean:

1. `listw` neighbour lists carry no `region.id`, so they were being compared
   positionally — 1,491 false regressions. Fixed by threading spot names in from
   the `STlist` and permuting weights in parallel with neighbours.
2. Elementwise relative difference was applied to kernel density tails, reporting
   96% discrepancies on curves agreeing to 1.1e-16. Replaced with a scale-relative
   metric.
3. Sorting keyless ggplot built data by its own float columns scrambled rows as
   soon as one column genuinely differed. Replaced with per-column multisets plus
   whole-row signatures.
4. Gate C was a global switch, so one real name-set mismatch reclassified 10,000
   genuinely order-only paths as regressions. Scoped per object.
5. The 5-sample pseudobulk fixture died on the fixture's deliberate zero-variance
   genes before reaching the heatmap, which is why delta 9 first showed as
   `MISSING_EXPECTED`.
